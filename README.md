# invisible-web

**How much of what an AI browser reads is text you cannot see?**

Web pages carry text that is present in the DOM but invisible to a human reader: screen-reader labels, collapsed mobile menus, `alt` and `aria-label` attributes, off-screen positioning, transparent elements. An agentic browser that reads the DOM rather than the rendered screen consumes all of it.

Palo Alto Unit 42 measured the [malicious version of this in the wild](https://unit42.paloaltonetworks.com/ai-agent-prompt-injection/) in March 2026 and catalogued 22 payload delivery techniques. Nobody has measured the benign baseline. Their conclusion names distinguishing benign from malicious prompts as the open problem for defenders. This repo measures the baseline.

## The number

For each page: **what share of the agent-readable text is invisible to a person.**

```
hidden_share = (hidden_words + attr_words) / (visible_words + hidden_words + attr_words)
```

### Current results

| Page | Words | hidden_share |
|---|---|---|
| Clean control page | 1,042 | **4.8%** |
| Fixture with 11 planted markers | 363 | 13.5% |

**4.8% is the floor, not zero.** The control page has no planted markers, no comments, no zero-width characters. Its 4.8% is entirely ordinary `alt`, `aria-label` and `placeholder` text, plus a collapsed mobile navigation menu. Both are legitimate, neither is concealment.

So real-site numbers get compared against 4.8%. A site at 6% is normal. The finding, if there is one, is in the tail.

## Method

Two snapshots per page, at load and at load plus ten seconds, so text injected on a delay shows up as a diff. `detect.js` walks every text node and every ancestor chain, records **all** reasons the text is not visible rather than the first, since concealment techniques stack. Findings are classified against Unit 42's taxonomy, so the output distribution is directly comparable to their telemetry.

```
sites.txt ──► run.py ──► extract.py ──► detect.js (in-page)
                │                          │
                ▼                          ▼
     out/summary.csv              out/<slug>.t{0,1}.json, .png
                                           │
                                           ▼
                                     analyze.py ──► out/distribution.csv
```

## Limitations, stated up front

**Single viewport.** Everything runs at 1440x900. A collapsed mobile menu is `display:none` here and visible at 375px. That is responsive design, not deception, and it inflates the number on nearly every site. A second pass at mobile width, keeping only text hidden at *both*, would isolate the harder signal. Not yet implemented.

**This is a floor, not a ceiling.** Unit 42's largest in-the-wild delivery category was visible plaintext at roughly 38%, usually in a footer nobody reads. This detector cannot see that by construction, because it is visible.

**Comments and unicode markers are excluded from the headline.** Opera documents Neon Do as reading the DOM tree and layout data rather than the markup, so HTML comments probably never reach the agent. Counted separately.

**Camouflage ignores `background-image`.** Effective background resolves from `background-color` only, walking up to the first non-transparent value. `clip-path` detection is a heuristic covering the two common cloaking shapes.

## Taxonomy

| Reason | Catches |
|---|---|
| `visual-concealment/css-rendering-suppression` | `display:none`, `visibility:hidden`, hidden `<textarea>` |
| `visual-concealment/zero-sizing` | `font-size:0`, `line-height:0`, zero-area box |
| `visual-concealment/off-screen-positioning` | box outside the document canvas, `text-indent` below -999 |
| `visual-concealment/transparency` | `opacity:0` on the element or an ancestor |
| `visual-concealment/camouflage` | text colour within a small distance of its background |
| `obfuscation/html-attribute-cloaking` | `alt`, `aria-*`, `title`, `placeholder`, `data-*` |
| `obfuscation/clip` | `clip: rect(0,0,0,0)`, zero-area `clip-path` |
| `dynamic-execution` | present at T1, absent at T0 |
| `markup/html-comment` | text in a comment node |
| `unicode/invisible-characters` | zero-width and formatting characters |
| `unicode/bidi-override` | bidirectional override and isolate characters |

Names are Unit 42's, verbatim. A finding carries every reason that applies: two of the eleven fixture markers legitimately trip two reasons each, without anyone trying to be clever.

## Usage

```bash
pip install -r requirements.txt
playwright install chromium

python3 -m pytest tests/ -v      # must be green before trusting any real number
python3 run.py                   # one URL per line in sites.txt
python3 analyze.py
```

## Fixtures

`fixtures/marker.html` is the local unit test: eleven planted markers, one per taxonomy reason, with exactly known word counts.

`evidence/` holds three pages generated by Opera Neon Make and served at live public URLs. They are the field fixtures, verified by hand against their HTML, CSS and JS, with `SHA256SUMS` and capture timestamps because they live on infrastructure I do not control.

| Directory | What it is |
|---|---|
| `evidence/v2-markers/` | Eleven markers, the primary field fixture |
| `evidence/v2-control/` | No markers. The 4.8% benign floor |
| `evidence/v1-partial/` | First generation. Reported six markers, delivered four |

`v1-partial` is kept deliberately. The generator's completion report did not match the artifact it delivered, and regenerating from the identical spec produced a complete page. The reliable observation is inconsistent completeness with consistent claims of completion. See `evidence/README.md`.

## Why the field fixtures matter

The local fixture proves the detector parses correctly. The Make-generated pages prove it works on pages it did not co-author, at public URLs any browser can reach. The control page in particular was not designed by me, and the detector's behaviour on it was predicted in advance and matched: attribute findings from `alt` and `aria-label` only, zero `data-*` findings below threshold, zero comments.
